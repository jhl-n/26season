# 모둠 협력 문제풀이 웹앱

6학년 과학 「1. 계절의 변화」 단원마무리를, 모둠(4인 기준, 결석 시 1~3인도
자동 대응)이 태블릿으로 함께 풀고 교사 대표 화면에서 실시간으로 진행
상황을 확인할 수 있는 앱입니다. 서버 프로그래밍 없이 정적 파일만으로
동작하며, Firebase Realtime Database를 데이터 동기화에 사용합니다.

## 구성 파일

```
season-app/
  index.html         학생/교사 화면으로 가는 진입 페이지
  student.html + js/student.js   학생용 화면 (학급→모둠→좌석→스테이션)
  teacher.html + js/teacher.js   교사 대표 화면 (반 탭 + 모둠×스테이션 현황판)
  js/stations-config.js  ★ 문제 내용 (이 파일만 바꾸면 다른 단원에 재사용)
  js/db-adapter.js        Firebase 또는 데모 저장소를 동일한 방식으로 다루는 어댑터
  js/firebase-config.js   Firebase 프로젝트 설정 (실제 수업 전 채워야 함)
  assets/                 문제에 필요한 교과서·실험관찰 사진
  css/style.css
  test/                   Playwright로 만든 자체 점검 스크립트 (선택사항)
```

## 1. 우선 데모 모드로 로직 확인해보기

`js/firebase-config.js`의 `apiKey`가 비어있으면 앱은 자동으로 **데모 모드**로
동작합니다. 데모 모드는 브라우저의 localStorage + BroadcastChannel을 이용해
**같은 브라우저의 여러 탭 사이에서만** 실시간 동기화됩니다. 실제 배포 전에
혼자 다음과 같이 테스트해볼 수 있습니다.

1. 이 폴더에서 아무 정적 서버나 실행 (예: `python3 -m http.server 8000`)
2. 브라우저 탭을 4~5개 열어 각각 `http://localhost:8000/student.html` 접속
   → 같은 반·같은 모둠을 선택하고 서로 다른 순서번호를 고르면 한 모둠을
     흉내낼 수 있습니다.
3. 탭 하나를 더 열어 `teacher.html`에서 그 반을 선택하면 실시간으로
   격자판이 바뀌는 것을 볼 수 있습니다.
4. 새 탭(시크릿 창 X, 같은 브라우저 창이어야 함)일수록 완전히 새 학생처럼
   동작합니다 (학생 화면은 탭 단위로 접속 정보를 기억합니다).

> ⚠️ 데모 모드는 인터넷 연결이나 Firebase 프로젝트 없이 로직을 확인하기
> 위한 것으로, 서로 다른 태블릿(기기)끼리는 동기화되지 않습니다. 실제
> 수업에는 반드시 아래 2번 과정을 거쳐 Firebase를 연결하세요.

## 2. 실제 수업용 Firebase 설정

1. https://console.firebase.google.com 에서 새 프로젝트를 만듭니다
   (학교 계정이 아니어도 개인 Google 계정으로 무료로 가능합니다).
2. 왼쪽 메뉴 **빌드 → Realtime Database** 에서 데이터베이스를 만듭니다.
   위치는 아무 곳이나 괜찮습니다.
3. **규칙(Rules)** 탭에서 학급용으로 간단히 아래처럼 설정합니다 (누구나
   읽기/쓰기 가능 — 링크를 아는 사람만 접근하는 교실용 프로토타입이므로
   충분하지만, 링크가 외부에 유출되지 않도록 주의하세요):
   ```json
   {
     "rules": {
       ".read": true,
       ".write": true
     }
   }
   ```
4. 프로젝트 설정(⚙️) → **일반** 탭 하단에서 "웹 앱 추가"(</> 아이콘)를
   눌러 웹 앱을 등록하고, 나오는 `firebaseConfig` 객체 값을 복사합니다.
5. `js/firebase-config.js`를 열어 그 값을 그대로 붙여넣습니다.
   (`databaseURL`이 반드시 포함되어 있어야 합니다 — Realtime Database를
   만들면 자동으로 생깁니다)
6. 저장 후 다시 열면 화면 상단 배지가 "실시간 동기화 중 ✅"으로 바뀝니다.

## 3. GitHub Pages로 배포하기

1. 새 GitHub 저장소를 만들고 이 `season-app` 폴더 안의 파일들을 그대로
   커밋·푸시합니다.
2. 저장소 **Settings → Pages**에서 배포 브랜치를 선택하면
   `https://<아이디>.github.io/<저장소이름>/` 주소가 생깁니다.
3. 학생 태블릿에는 `.../student.html`을 바로 북마크해주세요. (QR코드로
   만들어 나눠주면 접속이 더 빠릅니다) `index.html`(대문 화면)에는 교사
   화면으로 가는 버튼이 없고, **제목을 0.8초 이상 꾹 누르면**(마우스
   클릭&홀드 또는 태블릿에서 길게 터치) 교사 대표 화면으로 이동합니다 —
   학생 화면에는 이 방법이 안내되어 있지 않으므로, 선생님만 이 문서를
   보고 사용하시면 됩니다.
   > ⚠️ 다만 이건 "화면에 안 보이게" 숨긴 것일 뿐, 주소 자체
   > (`.../teacher.html`)를 아는 학생이 직접 입력하면 접속을 막지는
   > 못합니다. 완전히 막으려면 별도 비밀번호 확인 로직을 추가해야 하며,
   > 이번 버전에는 포함되어 있지 않습니다.

## 4. 다른 단원에 재사용하기

앱 코드(`student.js`, `teacher.js`, `db-adapter.js`)는 문제 내용을 전혀
모르는 상태로 짜여 있습니다. 다른 단원에 쓰려면:

1. `js/stations-config.js` 맨 위 `ACTIVITY_ID` 값을 새 문자열로 바꿉니다
   (예: `"science6-2-unit2-acid-base"`). **이걸 안 바꾸면 이전 단원 데이터와
   섞입니다.**
2. `ACTIVITY_TITLE`, `STATIONS` 배열을 새 단원 문제로 교체합니다. 각
   스테이션은 `items` 배열(문항마다 `kind: "ox" | "text" | "textarea"`,
   정답이 있으면 `answerKey`)로 구성되며, 파일 안의 주석에 자세히
   설명되어 있습니다. 사진이 필요한 문제는 `images: [{ src, alt,
   caption }]`를 추가하고 사진 파일을 `assets/`에 넣어주세요.
3. 필요하면 `CLASSES`(학급 목록)나 `GROUP_COUNT`, `MAX_SEATS_PER_GROUP`도
   조정합니다.
4. 나머지 파일은 손댈 필요가 없습니다.

## 5. 알아두어야 할 점 / 앞으로 손볼 수 있는 부분

- **모둠 안에 역할이 없습니다.** 모든 스테이션에서 모든 학생이 문항
  전체에 스스로 답을 입력해 제출하고(내 답), 모둠원의 답을 서로
  비교한 뒤, 모둠이 하나의 최종 답으로 합의해 **아무나** 제출·수정할
  수 있습니다. ("이번 스테이션엔 내가 쓸 부분이 없다"는 상황이
  생기지 않습니다 — 다만 그만큼 모둠원과 직접 말로 답을 맞춰보는
  과정이 중요해집니다.)
- **채점이 너그럽습니다.** 공백·괄호·조사 "의"를 무시하고, 정답 순서도
  가리지 않습니다. 예) `"태양 고도"` = `"태양고도"` = `"태양의 고도"`,
  `"㉠㉡"` = `"ㄱㄴ"`(원문자 없이 자음만 입력해도 정답) = `"ㄴㄱ"`(순서
  바뀌어도 정답), `"(가)"` = `"가"`. 자세한 로직은 `js/student.js`의
  `normalize`/`gradeField`를 참고하세요.
- **문항에 답이 없는 스테이션(글쓰기·토의)은 정답/오답 대신 "제출
  완료 ✅"로만 표시됩니다.** `js/stations-config.js`의 각 문항에
  `answerKey`를 적으면 자동채점되고, 적지 않으면 채점 없이 제출
  여부만 확인합니다.
- **교과서·실험관찰 사진이 필요한 문제에는 사진을 함께 보여줍니다.**
  ③번(지구가 태양 주위를 도는 위치 가/나), ④번(계절 삽화),
  ⑥번(앙부일구·원구일영) 스테이션에 실제 교과서/실험관찰 사진을
  넣어두었습니다 (`assets/` 폴더, 문제 설정은
  `js/stations-config.js`의 `images` 항목). 다른 단원으로 재사용할 때
  새 사진이 필요하면 이 폴더에 이미지를 추가하고 `images: [{ src, alt,
  caption }]`로 연결해주세요.
- 좌석은 "모둠당 그날 접속한 인원 수"로 자동 판단합니다. 결석한
  학생은 그냥 접속하지 않으면 되고, 역할 배정이 없으므로 인원수가
  바뀌어도 별도로 신경 쓸 게 없습니다.
- **제출 후 수정이 가능합니다.** 개인 답을 제출한 뒤에도 "✏️ 내 답
  수정하기" 버튼으로 다시 열어 고칠 수 있고, 모둠 최종 답도 제출 후
  결과가 화면에 표시된 채로 유지되며, 모둠원 누구든 "↩️ 모둠 답 다시
  논의하고 수정하기"를 누르면 언제든 다시 고쳐 제출할 수 있습니다.
- **다음 스테이션 이동은 자동이 아니라 수동입니다.** 모둠 최종 답을
  제출하면 곧바로 다음 문제로 넘어가지 않고, 그 자리에서 결과를
  확인한 뒤 모둠원 아무나 "다음 스테이션으로 이동 ▶" 버튼을 눌러야
  넘어갑니다. (오답이면 그 화면에서 바로 다시 논의해서 고쳐 제출할
  수 있습니다)
- 개인 답 제출·비교·채점·모둠 최종 제출·사진 표시 로직은 `test/`
  폴더의 Playwright 스크립트로 검증했습니다 (역할 없이 아무나 제출·
  수정 가능한지, 철자/원문자/순서가 달라도 채점이 맞는지, 실제 6개
  스테이션 전체, 사진 노출 여부, 교사 화면 반영까지 확인). 다시
  실행하려면:
  ```bash
  npm install -D playwright
  npx playwright install chromium   # 최초 1회
  python3 -m http.server 8843 &
  node test/flow_test.js
  ```
- **이름을 입력합니다.** 모둠 선택 다음, 순서번호 선택 전에 이름 입력
  단계가 있습니다. 이후 개인 답 비교표, 모둠 최종 제출자, 교사 대표
  화면의 모둠 칸 모두 번호 대신(또는 함께) 이름으로 표시되어 누구의
  답인지 바로 알 수 있습니다.
- **교사 화면 진입 버튼은 학생에게 전혀 표시되지 않습니다.** `index.html`
  제목을 0.8초 이상 눌러야 이동하며, 누르는 동안 화면에는 아무 표시도
  나타나지 않습니다(진행 바 등 눈에 띄는 표시는 일부러 넣지 않았습니다).
- 다음에 더 보완하면 좋을 것들 (이번 버전에는 없음): 학급별 좌석 잠금
  해제(예: 학생이 실수로 남의 좌석을 누르지 않게 확인창 추가), 하루
  일과 종료 후 5개 반 통합 리포트(반별 오답률 비교) 화면, 전체 타이머
  동기화.
